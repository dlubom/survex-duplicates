# 1.1.0 — Go executable and portable packages

The primary command is now a native Go executable. It preserves the detector's
input handling, exact geometric criterion, filters, record IDs and 47-column
CSV format. Running the text-dump workflow requires neither Go nor Python;
binary `.3d` input still requires Survex's `dump3d`.

- Six ZIP packages cover Linux, macOS and Windows on x86-64 and ARM64. Each
  includes the complete 18,584-leg KATASTER model, its text dump, provenance,
  license notices and all eight verified example reports.
- `--version` identifies the executable's version and source revision.
- The usage guide explains 5% versus 5 cm, both endpoint errors, reversed
  matches, station-name aliases and three real KATASTER examples.
- The Python implementation and locked environment remain an executable
  verification reference. The independent oracle and historical data are preserved.

The recorded migration investigation found byte-identical CSVs in all 160
comparisons and matching ordered exact results in all 320 tuple comparisons,
including both endpoint errors. Go was **6.02–14.73× faster** across the 23
measured scenarios on the recorded macOS ARM64 environment. The default registry
dump's median process time fell from 0.6335 s to 0.0492 s, and median peak RSS
from 84.1 MiB to 25.5 MiB. These measurements apply to those workloads and that
environment, rather than guaranteeing a speedup for every model. See the
[comparison method and complete evidence](https://github.com/dlubom/survex-duplicates/blob/main/experiments/go-2026-10-26/README.md).

The normal bundled report remains **218 pairs**, or **60** with
`--exclude-splays`. The explicit `--include-duplicates` audit remains **220**
or **62** respectively. A geometric match is still a candidate for survey
review, not an instruction to delete measurements.

Release automation checks all six native targets, verifies downloaded package
contents, executes the extracted demos and assembles one consistent asset set.
A version tag can publish only after those gates and an independent download
of the draft release's assets succeed. These prepared notes describe the
release content; they do not assert that remote CI has passed or publication
has occurred.
